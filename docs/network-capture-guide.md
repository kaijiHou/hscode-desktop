# HSCode 网络抓包使用手册

## 1. 功能用途

HSCode 网络抓包工具用于捕获和分析当前电脑的 TCP/UDP/ICMP 网络数据包。适用于：

- 调试本地网络服务
- 分析应用网络行为
- 排查连接问题
- 监控端口通信

## 2. 支持范围

| 协议 | 支持 |
|---|---|
| TCP | ✅ 完整支持 |
| UDP | ✅ 完整支持 |
| ICMP | ✅ 基础支持 |
| HTTP 单包检测 | ✅ 自动识别 |
| TLS/HTTPS 解密 | ❌ 不支持 |
| TCP 流重组 | ❌ 不支持 |
| HTTP/2 完整解析 | ❌ 不支持 |
| QUIC 解密 | ❌ 不支持 |

## 3. 如何打开

1. 打开一个会话
2. 点击底部工具栏的"网络抓包"
3. 首次使用需管理员权限

## 4. 页面区域

### 状态区

显示当前抓包状态：未开始 / 正在启动 / 正在抓包 / 正在停止 / 抓包失败

### 数据包计数

显示已捕获的数据包数量。

### 基础筛选

- **协议**：全部 / TCP / UDP / ICMP
- **IP**：按源/目标 IP 过滤
- **端口**：按源/目标端口过滤
- **方向**：全部 / 入站 / 出站

### 高级筛选

使用 HSCode 简化筛选语法（见第 9 节）。HSCode 会将其编译为 WinDivert 过滤表达式。

### 控制按钮

- **开始抓包**：启动捕获
- **停止抓包**：停止捕获
- **清空**：清空已捕获数据包

### 数据包列表

显示捕获的数据包，包含时间、方向、源地址、目标地址、协议、长度。

### 数据包详情

点击数据包后显示详细信息，包含概览、Payload、HEX、ASCII 四个标签页。

## 5. 开始抓包

1. 点击"开始抓包"
2. 状态变为"正在抓包"
3. 数据包列表开始显示捕获的数据
4. 点击任意数据包查看详情

## 6. 管理员权限说明

Windows 下网络抓包需要管理员权限（WinDivert 驱动要求）。

如果未以管理员身份运行：
- 点击"开始抓包"会显示权限错误提示
- 应用不会崩溃
- 需要以管理员身份重新启动 HSCode

## 7. 基础筛选

### 按协议筛选

在"协议"下拉框选择：
- **全部**：捕获所有协议
- **TCP**：仅捕获 TCP 数据包
- **UDP**：仅捕获 UDP 数据包
- **ICMP**：仅捕获 ICMP 数据包

### 按 IP 筛选

在"IP"输入框输入 IP 地址，同时匹配源地址和目标地址。

### 按端口筛选

在"端口"输入框输入端口号，同时匹配 TCP 和 UDP 端口。

### 按方向筛选

- **全部**：捕获所有方向
- **入站**：仅捕获进入本机的数据包
- **出站**：仅捕获从本机发出的数据包

## 8. 高级筛选语法

高级筛选使用 HSCode 简化筛选语法：

```
tcp                    # 仅 TCP
udp                    # 仅 UDP
icmp                   # 仅 ICMP
tcp.port == 22122      # TCP 端口 22122
udp.port == 53         # UDP 端口 53
src.ip == 192.168.1.1  # 源 IP
dst.ip == 10.0.0.1     # 目标 IP
```

复合表达式：

```
tcp and tcp.port == 22122
udp and dst.ip == 192.168.1.100
```

## 9. 数据包列表字段

| 字段 | 说明 |
|---|---|
| 时间 | 捕获时间（时:分:秒.毫秒）|
| 方向 | → 出站 / ← 入站 |
| 源地址 | 源 IP:端口 |
| 目标地址 | 目标 IP:端口 |
| 协议 | TCP / UDP / ICMP |
| 长度 | 数据包总长度（字节）|

## 10. 数据包详情

### 概览

显示协议、源地址、目标地址、长度、载荷长度、方向、IP 版本。

TCP 数据包额外显示：TCP 标志（SYN/ACK/FIN/RST/PSH/URG）。

HTTP 单包检测时显示：HTTP 方法、路径、版本、Host。

### Payload

显示载荷内容的文本预览。

### HEX

显示载荷的十六进制表示。

### ASCII

显示载荷的 ASCII 文本表示。

## 11. HTTP 单包检测

当一个 TCP 数据包的载荷包含完整的 HTTP 请求行时，HSCode 会自动识别：

```
GET /path HTTP/1.1
Host: example.com
```

**注意**：这是单包检测，不是 TCP 流重组。如果 HTTP 请求被分成多个 TCP 数据包，则无法识别。

## 12. Stop 行为

点击"停止抓包"后：
- 抓包引擎停止捕获新数据包
- 已捕获的数据包保留在列表中
- 继续生成的网络流量不会被记录

## 13. Clear 行为

点击"清空"后：
- 所有已捕获数据包被清除
- 数据包计数归零
- 详情面板清空
- 如果正在抓包，清空后继续捕获

## 14. 常见错误

| 错误 | 原因 | 解决 |
|---|---|---|
| "抓包需要管理员权限" | 未以管理员运行 | 以管理员身份重启 HSCode |
| "WinDivert DLL 缺失" | WinDivert 库未找到 | 重新安装 HSCode |
| "驱动缺失" | WinDivert 驱动未安装 | 以管理员运行自动安装 |
| "过滤器语法错误" | 高级筛选表达式非法 | 检查 filter 语法 |
| "抓包引擎不可用" | 非桌面版环境 | 使用 HSCode Desktop |

## 15. 安全边界和隐私

- 抓包数据仅在本地处理，不上传到任何服务器
- 抓包仅捕获本机网络流量
- 不解密 TLS/HTTPS 加密内容
- 建议仅在调试时使用，不要在公共网络上长时间抓包
